# Liftelo Backend Snapshot

## 1) Tech Stack
- Node.js + Express (API + server-rendered static HTML)
- MySQL (mysql2 promise pool)
- Session-based auth (`express-session` + MySQLStore)
- Multi-tenant model via `companies` table and `company_id` on all operational tables
- PDF generation via Puppeteer for RMS/Intervention/Work Order exports

## 2) Multi-tenant Architecture
- Tenant boundary is the `companies` table; every operational table includes `company_id`.
- Every authenticated request resolves `req.companyId` from session.
- API routes are guarded by `requireCompanyContext` in [`index.js`](index.js:35) to prevent missing tenant context.
- All read/write queries filter on `company_id` (hard requirement), including PDFs.
- Cross-company access is prevented by design and enforced in SQL joins.

## 3) Database Overview (by domain)
**Core tenancy**
- `companies`
- `users` (roles: admin, non-admin; `disabled_at` soft-disable)

**Locations & elevators**
- `locations` (includes `rms_frequency`)
- `elevators` (metadata, linked to locations)

**RMS (Regular Monthly Service)**
- `rms_visits` (append-only; `visit_date`, `created_at`, `rms_month`)
- `rms_visit_items` (per-elevator items, append-only)

**Interventions**
- `interventions`
- `intervention_items`

**Work Orders**
- `work_orders`
- `work_order_items`
- `work_order_users` (assignment M:N)

**Vehicles**
- `vehicles` (registration expiry, reminders)

**Projects**
- `projects`
- `project_sections`
- `project_tasks`
- `project_task_comments`
- `project_task_users` (task assignment M:N)

## 4) Key Business Logic
**RMS expectation & coverage**
- Expected months derived from `locations.rms_frequency`.
- Monthly attribution uses `COALESCE(rms_month, visit_date)`.
- Coverage logic (done/late/missing) computed in [`routes/home.js`](routes/home.js:11) using expected months + next-month grace rule.

**RMS alerts**
- Alert threshold: ≥3 consecutive missing expected RMS months.
- Computed in [`routes/home.js`](routes/home.js:104) from per-location visit history and expected month calculation.

**Work order lifecycle**
- Admin-only creation; assigned users via `work_order_users`.
- Status: open → completed/cancelled (explicit close, no delete).
- Overdue counts for notifications in [`routes/home.js`](routes/home.js:226).

**Projects progress**
- Progress derived from `project_tasks.is_completed` (no stored aggregate).
- Section and project progress calculated client-side in [`public/dashboard/project-detail.js`](public/dashboard/project-detail.js:110).

## 6) Security Enforcement
- Company scoping enforced by `requireCompanyContext` in [`index.js`](index.js:61).
- Admin-only routes via role checks in route handlers (e.g., [`routes/projects.js`](routes/projects.js:5)).
- Disabled users blocked and sessions invalidated in [`index.js`](index.js:42).
- PDFs generated by explicit record ID; queries must include `company_id` (see [`routes/rms-pdf.js`](routes/rms-pdf.js:1) and [`routes/intervention-pdf.js`](routes/intervention-pdf.js:1)).

## 7) Production Readiness (Current State)
- Stable, production-oriented structure with explicit tenant scoping and append-only RMS history.
- PDF generation is integrated and tenant-scoped.
- UI uses server-rendered HTML + vanilla JS; APIs are consistent for incremental modernization.

## 8) Known Weak Points / Technical Debt
- Limited automated tests (unit/integration) across routes and SQL logic.
- Some business logic lives in route handlers rather than a service layer.
- Error handling varies per route; structured error middleware could improve consistency.
- Session secret and environment configuration need hardening for production (rotation, secrets management).
- No explicit rate limiting or CSRF protection for session-based endpoints.

## 9) Migration Readiness for Modern Frontend (React)
- API surface already exists with JSON responses for all operational domains.
- Next steps: add CORS, token-based auth (optional), and versioned API paths.
- UI is currently server-rendered; migration can proceed page-by-page without backend rewrite.

## 10) Stable & Production-Safe Components
- Multi-tenant scoping (`company_id`) and session-based auth enforcement.
- RMS append-only history with explicit monthly attribution.
- Work orders lifecycle and assignment model.
- PDF generation tied to explicit IDs and tenant constraints.
- Project/task structure with M:N assignment via `project_task_users`.
